\subsection{Client update and shared aggregation}
Each federated local epoch is a full-batch SGD step over that client's
training positives, using one fresh uniform negative per positive. This
normalizes the loss within a user. Repeated item indices in positive and
negative samples accumulate their gradients. Only touched item rows receive
local loss gradients, but private aggregation subsequently adds noise to
every shared coordinate. Item rows not touched by any user therefore can
still change in a private round.

\begin{enumerate}[label=\arabic*.]
\item Sample each eligible user independently with public inclusion probability
$q$. Preserve the selected cohort for all shared and local computations.
\item For each selected user, copy the common shared state and retrieve its
local vector. Repeat $E=2$ times: draw negatives from the training-only mask,
compute the within-user mean BPR loss and explicit regularizer, and update
both the local vector and the client's shared copy.
\item Persist the new local vector. Form the difference between the client's
shared copy and the round's starting state. For a private run, jointly clip
that whole difference to norm $C$.
\item Sum the contributions. In private runs, add an independent Gaussian
vector with SD $\sigma C$, even when no user was selected. Divide by fixed
$qN$ and multiply by $\eta_s$. Nonprivate B1 instead averages over realized
participants and skips an empty round.
\item Update the server's shared state. Where specified, rebalance the two
factors without changing their product. Record communication and diagnostics
at the protocol's declared observation points.
\end{enumerate}
This procedure describes the simulator's semantics. It does not specify
a network protocol, secure-aggregation implementation, or availability model.

\subsection{Diagnostic random streams and identity checks}
E2 pulse streams use the tuple (training seed, 6702, pulse replicate).
Future client, negative, and Gaussian streams use identifiers 6703, 6704,
and 6705 respectively. Common streams are retained across branches and
pulse amplitudes. E3 uses separately declared dataset-coded streams with
identifiers 6710--6713 and observer selection identifier 6708. E4 uses
its own fixed observer selection. Exact seed tuples are part of the
frozen protocols and saved records, so a report rerender does not generate
new diagnostic observations.

Synthetic checks compare zero-pulse branches with their references and
both-reset branches over continued rounds. Shared resets enforce identical
$Q$; local resets enforce identical $P$. The score decomposition includes
all cross inner products. Alignment checks measure relative product error
instead of assuming exact equality in float32. E4 checks moment formulas
within Monte Carlo uncertainty and audits quadrature diagnostics separately.
These checks support the implemented experiments; they do not prove an
unrestricted mathematical correctness claim for every numerical state.

\subsection{Numerical environment and reproducibility precision}
The pinned research environment records NumPy 2.2.6, pandas 2.3.3, SciPy
1.15.3, PyTorch 2.14.0+cpu, Opacus 1.6.0, matplotlib 3.10.9, and the
remaining versions in the curated requirements file. Opacus is used for
accountants, not a PrivacyEngine wrapping these models. Training and
diagnostic observer precision are distinguished: model updates retain
float32, while relevant diagnostic norms and closures use float64.
E1 enforces one numerical worker thread; older centralized runs used
their recorded CPU/thread configuration.

A fresh-environment historical B0 reproduction was identical to reported
metric precision but not byte-identical for seed 42. Relative weight
difference was approximately $7.8\times10^{-6}$, and one validation
rank changed from 596 to 595 without changing reported six-decimal
metrics. A floating-point kernel explanation was plausible but unverified.
Accordingly the report promises recorded seeds, environments, artifacts,
and numerical audits, not universal bitwise identity on different systems.
